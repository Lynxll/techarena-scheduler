# TechArena: планировщик задач с дедлайнами

Исследовательский проект на C++17 для задачи TechArena MSU: планирование связанных задач на вычислительных ядрах с ограничениями памяти и взаимным влиянием параллельных вычислений.

Решение включает эвристический планировщик, событийную модель исполнения и локальные проверки. Основной интерес проекта — перевод сложных требований в модель, работа с ограничениями, проверка допущений и разбор расхождений между локальным и внешним оцениванием.

> **Статус:** экспериментальный MVP. В сохранённом отчёте две конкурсные отправки получили по 19 TLE и одному WA.

## Задача

На вход поступают графы зависимых задач - DAG. У каждой задачи есть приоритет, относительный дедлайн, объём вычислений, загрузки и записи данных. Планировщик выбирает допустимый поток ядра и момент старта с учётом:

- зависимостей между задачами и времени поступления DAG;
- вычислительной мощности и совместимости ядер;
- общей SRAM ядра и конфликтов доступа к DRAM;
- влияния одновременно выполняемых задач друг на друга;
- ограниченного количества вызовов планировщика.

Результат - назначения через интерфейс `arena::IScheduler` и запрос следующего полезного события. Библиотека не содержит собственного `main()`; для локального запуска служат пример и тестовые программы.

## Подход

1. Для поступившего DAG оцениваются минимальная длительность задач, критический путь и последнее допустимое время старта с учётом дедлайнов потомков.
2. Готовые задачи упорядочиваются по последнему времени старта, приоритету и критическому пути.
3. Ядра ранжируются по оценке длительности с учётом текущей нагрузки и памяти.
4. Кандидат на запуск проверяется событийным прогнозом на копии состояния. В рамках принятой модели запуск отклоняется, если он нарушит дедлайн кандидата или активной задачи.
5. После окончания записи освобождаются ресурсы и становятся доступными зависимые задачи.

Это жадная эвристика: допустимость отдельных назначений не доказывает выполнимость всего DAG и не гарантирует оптимальное расписание.

## Архитектура и навигация

- [`scheduler.cpp`](scheduler.cpp) — очередь готовых задач, анализ DAG и выбор назначений.
- [`execution_model.h`](execution_model.h), [`execution_model.cpp`](execution_model.cpp) — фазы загрузки, вычисления и записи, конкуренция за ресурсы, прогноз завершений.
- [`spec_system.h`](spec_system.h), [`spec_scheduler.h`](spec_scheduler.h) — предоставленный интерфейс задачи.
- [`runner_example.cpp`](runner_example.cpp) — исходный пример интеграции.
- [`tests/test_main.cpp`](tests/test_main.cpp) — 22 группы локальных проверок, включая граничные времена, память, DAG и масштабные сценарии.
- [`tests/reference_replay.cpp`](tests/reference_replay.cpp) — отдельный replay для сопоставления назначений с независимым расчётом.
- [`docs/requirements.ru.md`](docs/requirements.ru.md) — разбор требований.
- [`docs/implementation.ru.md`](docs/implementation.ru.md) — устройство и обоснование решения.
- [`docs/validation.ru.md`](docs/validation.ru.md) — журнал проверок и найденных ошибок.
- [`docs/contract-questions.ru.md`](docs/contract-questions.ru.md) — открытые вопросы о контракте; это черновик, а не ответы организаторов.
- [`docs/plan.ru.md`](docs/plan.ru.md) — дальнейшие направления работы.

## Сборка и запуск

Команды выполняются из корня репозитория. В репозиторий не включены компиляторы, собранные программы и зависимости окружения.

### Windows и MSVC

Нужны Visual Studio 2022 или Build Tools с компонентом C++.

```powershell
powershell -NoProfile -File tools/build.ps1
./build/tests.exe --demo
./build/runner_example.exe
```

Скрипт собирает пример и тесты с C++17, оптимизацией и предупреждениями как ошибками, затем запускает основной набор проверок. Он не запускает отдельный `reference_replay`.

### Windows и GCC

Нужен установленный `g++`, доступный через PATH. Можно передать путь к компилятору параметром `-Compiler`.

```powershell
powershell -NoProfile -File tools/build_gcc.ps1
```

Скрипт собирает и запускает основные тесты, demo, независимый replay и исходный пример. Журнал записывается в `build/gcc/validation.log`. У обоих скриптов есть параметр `-SkipTests` для сборки без запуска.

Для обычного GCC доступны и прямые команды; они описывают сборку, но не означают, что эта копия проверена на Linux:

```sh
g++ -std=c++17 -O2 -Wall -Wextra -Werror -DNDEBUG -o runner_example runner_example.cpp scheduler.cpp execution_model.cpp
g++ -std=c++17 -O2 -Wall -Wextra -Werror -DNDEBUG -I. -o tests_local tests/test_main.cpp scheduler.cpp execution_model.cpp
g++ -std=c++17 -O2 -Wall -Wextra -Werror -DNDEBUG -I. -o reference_replay tests/reference_replay.cpp scheduler.cpp execution_model.cpp
./tests_local
./tests_local --demo
./reference_replay
```

### Подготовка конкурсного архива

```powershell
powershell -NoProfile -File tools/export_submission.ps1
```

Скрипт создаёт `output/submission` и `output/mvp-source.zip` с пятью файлами библиотеки. Для выполнения такого архива требуется runner организатора.
